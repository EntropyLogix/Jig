`blt` builds and runs only on Linux and macOS. Windows works today only through WSL with the Linux binary. Make `blt` a native Windows program.

## What is Unix-only today

- `store::atomic_write` imports `std::os::unix::fs::{OpenOptionsExt, PermissionsExt}`: it creates the temporary file with mode 0600 and copies the old file's mode onto the replacement. On Windows there are no Unix modes; the file inherits the directory's ACL.
- `ident` already guards its 0600 salt file with `#[cfg(unix)]`.
- Locking already uses `std::fs::File::lock`, which maps to `LockFileEx` on Windows, so `.blt/.lock` needs no new code. Replacing a file uses `std::fs::rename`, which on Windows is `MoveFileExW` with replace-existing; it fails while another process holds the target open, and that must surface as a clear error.
- Several tests use Unix symlinks and permission bits and need Windows equivalents or `cfg(unix)`.

## Scope

1. The library and `blt` compile for `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`; Unix permission handling is behind `cfg(unix)`, with no behavior change on Unix.
2. The test suite runs on a Windows CI runner; tests that need Unix features are gated, and Windows-specific behavior (CRLF, path separators in messages, a file held open during replace) has coverage.
3. Releases (B5) add `blt-<version>-<target>.zip` for both Windows targets to the same `SHA256SUMS`.
4. `install.ps1` for `irm https://raw.githubusercontent.com/EntropyLogix/Billet/main/install.ps1 | iex`: picks the architecture, downloads the latest release (or `-Version`), verifies the checksum, installs `blt.exe` into a user directory on `PATH`, and changes nothing on failure.
5. README lists Windows install and states that crew needs a POSIX shell (Git Bash or WSL).

## Out of scope

- Scoop bucket, winget manifest, code signing.
- Porting the crew shell scripts to PowerShell.

## Depends on

B5 (release workflow and archives).

## Done when

- CI builds and tests on Windows, and a release tag produces both Windows zips.
- On Windows, `install.ps1` installs a `blt --version` that matches the tag, `blt init` in a project writes `.blt/`, `AGENTS.md`, and the hooks, and two `blt` processes writing at once serialize through `.blt/.lock`.
