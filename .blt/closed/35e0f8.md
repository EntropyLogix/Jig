Today `blt` installs only with `cargo install`, so every machine needs a Rust toolchain and compiles each release. Ship prebuilt binaries instead, the way most Rust CLIs do.

## Scope

1. A GitHub Actions workflow in this repository runs when a `v*` tag is pushed. It builds `blt` for:
   - macOS arm64 and x86_64;
   - Linux x86_64 and arm64 as static musl binaries, so they run on any distribution and in WSL.
   It publishes a GitHub Release for the tag with one `blt-<version>-<target>.tar.gz` per target, containing `blt`, `LICENSE`, and `licenses/`, plus a `SHA256SUMS` file. The build runs the test suite first; a failing suite publishes nothing.
2. A Homebrew tap, `EntropyLogix/homebrew-tap`, with `Formula/blt.rb` that installs the prebuilt binary for the machine's platform on macOS and Linux. `brew install entropylogix/tap/blt` installs it and `brew upgrade` updates it.
3. Each release updates the formula: version, URLs, and checksums come from that release's `SHA256SUMS`. If the workflow cannot push to the tap (no token configured), the release still succeeds and the formula is updated by hand from `SHA256SUMS`.
4. `install.sh` in this repository for machines without Homebrew: `curl -fsSL https://raw.githubusercontent.com/EntropyLogix/Billet/main/install.sh | sh` detects OS and architecture, downloads the latest release (or `--version X.Y.Z`), verifies the checksum, and installs `blt` into `~/.local/bin` (or `--dir DIR`). It refuses an unsupported platform or a checksum mismatch and changes nothing then.
5. README Install section lists Homebrew first, then `install.sh`, then `cargo install` for people who build from source.

## Out of scope

- Native Windows (WSL uses the Linux binary). Tracked separately if needed.
- Shipping the crew skill in the Homebrew package.
- Publishing to crates.io.

## Done when

- Pushing a release tag produces a GitHub Release with four archives and `SHA256SUMS`, and only after the tests pass.
- On a Mac, `brew install entropylogix/tap/blt` installs a `blt --version` that matches the tag, and `brew upgrade` moves to the next tag.
- On Linux without Homebrew (this container), `install.sh` installs the same version and rejects a tampered checksum.
