## Closing Summary

> crew/ review workflow (dev, audit, cross-check, lead) with bin/crew, templates and crew_review_loop test; Jig tracks its own work; test scratch dirs moved to the system temp dir

Add `crew/`: an optional review workflow on top of Jig, shipped in this
repository but outside the binary. Jig itself does not change.

Contract:
- One skill entry point `jig-crew` for Claude Code (`/jig-crew ROLE ...`)
  and Codex (`$jig-crew ROLE ...`), invoked only explicitly
  (`disable-model-invocation: true`; Codex `agents/openai.yaml`
  `allow_implicit_invocation: false`).
- Roles `dev`, `audit` (with `--cross-check`), `lead`. Each role lives in its
  own file; a session receives only its role's instructions.
- Script `crew/bin/crew` (POSIX sh, git, jq, jig) does the mechanical part:
  checks status and label, computes the round, creates the round directory
  and files from templates, prints the paths to read and write, computes and
  verifies the code fingerprint, and prints the role instructions.
- A round is one `jig review`; its number is the count of
  "submitted for review" entries in the history. Documents live in
  `.jig/docs/ID/review/round-NN/`: `handoff.md` (developer), `audit-LABEL.md`
  (auditors), `audit-lead.md` and `decision.md` (lead). The developer reads
  only `decision.md`.
- `review` freezes the code. The fingerprint (HEAD, diff, untracked files,
  excluding `.jig/`) is recorded in the handoff; a mismatch is reported
  loudly, not blocked.
- Labels are required by crew (Jig's `--by` stays optional). Invoking `lead`
  for an issue is the person's permission to run `rework` on it; `close`
  stays with the person.
- Prompts are English; agents reply and write documents in the person's
  language (the issue's language when the person has not written yet).
- README gets an "Optional: jig-crew" section; the test suite covers one
  dev -> review -> rework -> review loop through `crew` so a change in Jig's
  history wording breaks a test, not a user.
