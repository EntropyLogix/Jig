## Closing Summary

> Handles <prefix><number> with opaque keys; .jig/config.json prefix; number field and update --number; duplicate-number and config problems; handles in all output; migrator assigns keys and legacy numbers

People and agents refer to issues by a sequential handle with a
per-project prefix (`B494`, `AN-12`); the random key stays internal.
Decisions D1–D10 and the approach: architecture.md in this issue's
documents.

Done when:
- Keys are six lowercase hex digits with at least one letter, no prefix;
  files and documents directories are named by key.
- Top-level issues have a required `number`; `add` assigns max + 1 under
  the lock, open and closed included; subtasks have `number: null` and the
  handle of their root plus the dotted part.
- `.jig/config.json` holds the prefix (default `B`, confirmed; set by
  `jig init --prefix`); `check` validates it; changing it changes every
  handle.
- No human-facing output contains a key except inside a path; JSON `id`
  is the handle and JSON adds `key`; MCP output equals CLI output.
- Commands accept a handle case-insensitively, a bare number, or a key;
  an ambiguous handle is refused and names every match.
- A duplicate number is warned once by `list`, `ready`, and `tree`,
  reported by `check`, and fixed with `jig update HANDLE --number N`
  (unused, top-level, recorded in history).
- `B440` and `B-xxxxxx` formats and the hex shorthand are gone; SPEC and
  README describe only the new form; the agent block tells agents to use
  handles only.
- The test families cover handles, keys, numbering, duplicates, and the
  config; gates pass on stable and 1.89; crew prints handles.
- Tag `v1.0.0` is removed now and set on the commit that completes this
  issue. After release the registries in Jig, Forge, and AnomalyProtocol
  are recreated or fixed by hand, and Jig is removed from EntropyForge.
